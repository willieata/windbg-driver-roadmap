從零開始:Driver 開發與 WinDbg 除錯 · 29 週

每週任務下方附延伸資源(官方文件、書籍章節、實作 lab)。左側圓點是中斷點樣式的任務開關,點擊切換完成狀態,進度會自動保存。

Stage 1 — 地基補強(Week 01–13)
PHASE 00

C/C++ 地基強化

WEEK 01–04
W1Pointer 與記憶體模型

stack vs heap 的差異、pointer arithmetic、function pointer 語法與用途——driver 裡到處都是 callback,這是必練基礎。

  • K&R,《The C Programming Language》第 5 章 Pointers and Arrays
  • cppreference.com — Pointer declaration
W2Struct / 記憶體佈局

struct/union 的 alignment 與 padding,手刻一個簡單的 binary parser 練習欄位對齊,這觀念之後看 dt 輸出會直接用到。

  • K&R 第 6 章 Structures, Unions
  • cppreference.com — Struct declaration
W3手動記憶體管理

malloc/free 生命週期,認識並親手重現 dangling pointer、double free、use-after-free 這幾種典型 bug。

  • Clang — AddressSanitizer 文件(抓 use-after-free / double free)
  • Valgrind — Memcheck 手冊
W4綜合小專案

實作一個 linked list,搭配自己寫的 memory pool allocator——這正是 driver 開發裡常見的手法。

  • 無指定教材,重點是實作與用 W3 的工具驗證自己沒有 leak / UAF
PHASE 01

OS 基礎概念

WEEK 05–06
W5Process / Thread / 排程

context switch 概念、kernel mode 與 user mode 的界線、syscall 如何跨越這條界線進入核心。

  • Microsoft Learn — About Processes and Threads
  • Pavel Yosifovich 等著,《Windows Internals》Part 1,Ch.1–2
W6虛擬記憶體與分頁

virtual address space、page table 基本概念,先搞懂這塊,之後才會知道為什麼 driver 要在意 IRQL。

  • Microsoft Learn — About Memory Management
  • 《Windows Internals》Part 1,Ch.5 Memory Management
PHASE 02

組語 / Calling Convention

WEEK 07–09
W7x64 暫存器與基本指令

mov / lea / push / pop / call / ret,通用暫存器在函式呼叫過程中各自扮演的角色。

  • Microsoft Learn — x64 Architecture Overview and Registers
  • Randall Hyde,《The Art of 64-Bit Assembly》第 2–3 章
W8Calling Convention 與 Stack Frame

x64 fastcall、prologue/epilogue,練到能看懂一段組語裡的呼叫堆疊實際在做什麼。

  • Microsoft Learn — x64 Calling Convention
  • NTDebugging Blog — Challenges of Debugging Optimized x64 Code
W9原始碼對照組語

編譯自己寫的簡單 C 程式,用 IDA 對照組語驗證理解——這塊你已經有底子,重點是把組語跟 C 語意接起來。

  • 用自己熟悉的 IDA(Hex-Rays 官方文件:docs.hex-rays.com)搭配 W7–8 的資料對照
PHASE 03

Driver 開發入門

WEEK 10–13
W10開發環境建置

安裝 WDK,建立 Visual Studio driver 專案,設定 test signing 與測試機(這台之後也會拿來做 kernel debug target)。

  • Microsoft Learn — Getting Started with Windows Drivers
W11第一個 WDM Driver

寫出 DriverEntry 與 Unload,建立最基本的 IOCTL 通訊架構。

  • Microsoft Learn — Introduction to WDM
  • Microsoft Learn — Choosing a Driver Model
W12IRP 與 Dispatch Routine

理解 IRP 是什麼、Major Function Table 的角色,寫一個簡單的 dispatch routine 處理請求。

  • Microsoft Learn — I/O Request Packets
  • Microsoft Learn — Creating IOCTL Requests in Drivers
W13KMDF 入門

對比 WDM,理解框架幫你簡化了哪些部分,把 W11–12 的功能改用 KMDF 重寫一次。

  • Microsoft Learn — Write a KMDF Driver Based on a Template
Stage 2 — WinDbg 除錯(Week 14–29)
PHASE 04

環境與基礎指令

WEEK 14–15
W14安裝與 Symbol 設定

安裝 WinDbg Preview,設定 _NT_SYMBOL_PATH,練習 .reload /f、lm、dt、x 對一般 user-mode process。

  • Microsoft Learn — Symbol Path for Windows Debuggers
  • Microsoft Learn — Setting Symbol and Executable Image Paths in WinDbg
W15User-mode 除錯練手感

寫一個會觸發 access violation 的小程式,attach 抓下來。練 bp / bl / bc、k、dv。

  • Mario Hewardt、Daniel Pravat,《Advanced Windows Debugging》第 1–3 章
PHASE 05

Kernel Debug 環境

WEEK 16–17
W16Named Pipe / COM 除錯

用 W10 建的 target VM 接 kernel debug:windbg -k com:pipe,port=\\.\pipe\xxx,resets=0。

  • Microsoft Learn — Kernel-Mode Debugging of a VM via Virtual COM Port
W17KDNET 網路除錯

bcdedit /debug on、bcdedit /dbgsettings net,並理解 kd -kl local kernel debug 的限制。

  • Microsoft Learn — Set Up KDNET Manually
  • Microsoft Learn — Set Up KDNET Automatically
PHASE 06

核心資料結構

WEEK 18–19
W18Driver / Device Object

dt nt!_DRIVER_OBJECT、dt nt!_DEVICE_OBJECT,對照 !drvobj、!devobj、!devstack 的輸出,跟自己 W11 寫的 driver 對照。

  • Microsoft Learn — !drvobj
  • Microsoft Learn — !devobj
W19Device Stack / PnP 樹

!devnode 理解 device stack 與 PnP 樹狀結構。

  • Microsoft Learn — !devstack
  • Debugger commands that make my life easier(實戰範例)
PHASE 07

IRP 追蹤

WEEK 20–21
W20IRP 基礎指令

!irp、!irpfind,在自己 W12 寫的 dispatch routine 下 bp,觀察 IRP 進來的當下狀態。

  • Microsoft Learn — !irp
  • Microsoft Learn — 官方手把手 Lab:Debug Windows Drivers(Echo Kernel Mode)
W21完整 IRP 生命週期

追一條 IRP 從建立到 IoCompleteRequest 的完整流程,搭配 k、dv 還原呼叫堆疊。

  • Microsoft Learn — _IRP (wdm.h) 結構詳解
PHASE 08

記憶體 / IRQL

WEEK 22–23
W22Pool 分析

!pool、!poolused 理解 pool tag,搭配 Pool Monitor 抓記憶體洩漏。

  • Microsoft Learn — !poolval
  • Microsoft Learn — !pool
W23分頁與 IRQL 規則

!pte、!vtop、!address,搞懂 DISPATCH_LEVEL 不能碰 paged pool 這條規則,這是多數當機的根源。

  • Microsoft Learn — !pte
  • Microsoft Learn — Managing Hardware Priorities(IRQL 規則)
  • What is IRQL?(概念說明,推薦先讀這篇)
PHASE 09

Dump 分析

WEEK 24–25
W24Crash Dump 起手式

產生 kernel dump,!analyze -v 起手,搭配 .trap、.cxr 還原當機當下的 context。

  • Microsoft Learn — Using the !analyze Extension
  • Microsoft Learn — Analyze a Kernel-Mode Dump File by Using WinDbg
W25Driver Verifier 實戰

開啟 Driver Verifier(special pool、IRQL checking、DMA 驗證),故意讓自己的 driver 炸掉,用前面學的指令修復。

  • Microsoft Learn — How to Use Driver Verifier for Driver Testing
  • Microsoft Learn — Driver Verifier Options
PHASE 10

TTD / Scripting

WEEK 26–27
W26Time Travel Debugging

錄製與回放執行過程,!tt、dx @$cursession,抓一次難重現的 race condition。

  • Microsoft Learn — Time Travel Debugging Overview
  • Microsoft Learn — TTD Sample App Walkthrough
W27資料模型與自動化

dx 資料模型與 JavaScript extension,寫一個自己的 debugger extension 自動列出特定結構欄位。

  • Microsoft Learn — TTD.exe Command Line Utility
  • Microsoft Learn — WinDbg: Time Travel Timelines
PHASE 11

反除錯整合

WEEK 28–29
W28除錯偵測手法

KdDebuggerEnabled、SharedUserData 偵測手法,理解 anti-cheat 如何偵測 WinDbg 附掛。

  • Alex Matrosov、Eugene Rodionov、Sergey Bratus,《Rootkits and Bootkits》相關章節
  • OSR Online 論壇(osronline.com)搜尋 anti-debug / KdDebuggerEnabled 討論串
W29綜合實戰

把自己的 driver 放進有反偵測意識的情境,同時練習「隱蔽除錯」與「偵測繞過」兩個角度,收斂整個 29 週的技巧。

  • 無新教材,回顧 W1–28 的筆記與自己的 driver 專案進行整合演練
核心書單: Pavel Yosifovich 等著《Windows Kernel Programming》、《Windows Internals》(Part 1 & 2)、Mario Hewardt & Daniel Pravat《Advanced Windows Debugging》、Randall Hyde《The Art of 64-Bit Assembly》。
